# Events API

Простой REST API для управления событиями на **ASP.NET Core Web API** (.NET 10).
Данные о событиях хранятся в памяти приложения (in-memory), поэтому при перезапуске сервиса они очищаются.

## Требования

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) (или выше)

## Запуск проекта

```bash
dotnet build WebApp.slnx
dotnet run --project WebApp.csproj
```

> В каталоге репозитория находятся и файл решения `WebApp.slnx`, и файл проекта `WebApp.csproj`,
> поэтому при сборке и запуске нужно явно указывать файл.

После запуска API будет доступен по адресам (см. `Properties/launchSettings.json`):

- HTTP: `http://localhost:5238`
- HTTPS: `https://localhost:7118`

Swagger UI: http://localhost:5238/swagger (или https://localhost:7118/swagger)

## Запуск тестов

```bash
dotnet test WebApp.slnx
```

Тесты написаны на [xUnit](https://xunit.net/) и лежат в отдельном проекте `tests/EventService.Tests`.
Они покрывают CRUD-операции `EventService`, неуспешные сценарии (несуществующий идентификатор,
некорректные данные), фильтрацию по названию и датам, пагинацию и комбинированную фильтрацию.

## REST API

### GET /events

Возвращает страницу событий с фильтрацией.

**Query-параметры:**

| Параметр   | Тип      | Обязательный | По умолчанию | Описание                                                        |
|------------|----------|--------------|--------------|-----------------------------------------------------------------|
| `title`    | string   | нет          | —            | Поиск по названию: регистронезависимое частичное совпадение     |
| `from`     | DateTime | нет          | —            | События, которые начинаются не раньше указанной даты            |
| `to`       | DateTime | нет          | —            | События, которые заканчиваются не позже указанной даты          |
| `page`     | int      | нет          | `1`          | Номер возвращаемой страницы (значения меньше 1 приводятся к 1)  |
| `pageSize` | int      | нет          | `10`         | Количество элементов на странице (от 1 до 100)                  |

Все фильтры комбинируются логическим **И**: применяются только переданные параметры.

**Примеры запросов:**

```
GET /events
GET /events?title=Мероприятие
GET /events?from=2026-01-01T00:00:00Z&to=2026-12-31T23:59:59Z
GET /events?title=Мероприятие&from=2026-01-01T00:00:00Z&to=2026-06-30T23:59:59Z&page=2&pageSize=5
```

**Ответ:** `200 OK`

```json
{
  "totalCount": 2,
  "page": 1,
  "pageSize": 2,
  "items": [
    {
      "id": "3f6b3d1a-6a1e-4b7f-9a2c-5e1c2d3c4d5e",
      "title": "Мероприятие",
      "description": "Описание мероприятия",
      "startAt": "2026-01-15T10:00:00Z",
      "endAt": "2026-01-15T18:00:00Z"
    },
    {
      "id": "8a1c2d3e-4f50-4a6b-8c7d-9e0f1a2b3c4d",
      "title": "Мероприятие по безопасности",
      "description": null,
      "startAt": "2026-02-20T09:00:00Z",
      "endAt": "2026-02-20T13:00:00Z"
    }
  ]
}
```

Где:

- `totalCount` — общее количество событий, удовлетворяющих фильтру (без учёта пагинации);
- `page` — номер текущей страницы;
- `pageSize` — количество элементов на текущей странице;
- `items` — события текущей страницы.

### GET /events/{id}

Возвращает событие по идентификатору.

**Ответ:**
- `200 OK` — событие найдено
- `404 Not Found` — событие не найдено

### POST /events

Создаёт новое событие. Идентификатор генерируется автоматически.

**Тело запроса:**

```json
{
  "title": "Мероприятие",
  "description": "Описание мероприятия",
  "startAt": "2026-01-15T10:00:00Z",
  "endAt": "2026-01-15T18:00:00Z"
}
```

**Ответ:**
- `201 Created` — событие создано, в теле — созданное событие
- `400 Bad Request` — нарушена валидация

### PUT /events/{id}

Обновляет событие целиком.

**Тело запроса:** то же, что и для `POST /events`.

**Ответ:**
- `200 OK` — событие обновлено
- `400 Bad Request` — нарушена валидация
- `404 Not Found` — событие не найдено

### DELETE /events/{id}

Удаляет событие.

**Ответ:**
- `204 No Content` — событие удалено
- `404 Not Found` — событие не найдено

## Формат ошибок

Все ошибки возвращаются в едином формате [Problem Details (RFC 7807)](https://datatracker.ietf.org/doc/html/rfc7807)
с `Content-Type: application/problem+json`. Ответ формирует middleware глобальной обработки исключений,
поэтому формат одинаков для всех типов ошибок.

**Коды ответов:**

| Код                       | Когда возвращается                                                        |
|---------------------------|---------------------------------------------------------------------------|
| `400 Bad Request`         | Ошибка валидации модели запроса или бизнес-правил сервиса                  |
| `404 Not Found`           | Запрошенный ресурс не существует                                          |
| `500 Internal Server Error` | Непредвиденная ошибка; детали не раскрываются, диагностика — в логах сервера |

**Пример ошибки валидации (400):**

```json
{
  "title": "Ошибка валидации",
  "status": 400,
  "detail": "EndAt должен быть позже StartAt.",
  "instance": "/events",
  "traceId": "0HN7Q2B7Q6G6T:00000001"
}
```

Для ошибок валидации модели дополнительно возвращается объект `errors` с разбивкой по полям:

```json
{
  "title": "Ошибка валидации",
  "status": 400,
  "instance": "/events",
  "errors": {
    "Title": ["Поле Title обязательно."]
  },
  "traceId": "0HN7Q2B7Q6G6T:00000002"
}
```

**Пример ошибки «ресурс не найден» (404):**

```json
{
  "title": "Ресурс не найден",
  "status": 404,
  "detail": "Событие с id '3f6b3d1a-6a1e-4b7f-9a2c-5e1c2d3c4d5e' не найдено.",
  "instance": "/events/3f6b3d1a-6a1e-4b7f-9a2c-5e1c2d3c4d5e",
  "traceId": "0HN7Q2B7Q6G6T:00000003"
}
```

**Пример непредвиденной ошибки (500):**

```json
{
  "title": "Внутренняя ошибка сервера",
  "status": 500,
  "detail": "Произошла непредвиденная ошибка. Попробуйте повторить запрос позже.",
  "instance": "/events",
  "traceId": "0HN7Q2B7Q6G6T:00000004"
}
```

## Валидация входных данных

- `title` — обязательное поле;
- `startAt` — обязательное поле;
- `endAt` — обязательное поле;
- `endAt` должен быть позже `startAt`;
- `description` — опциональное поле.

При нарушении валидации сервис возвращает `400 Bad Request` в формате Problem Details.

## Поля модели Event

| Поле          | Тип      | Обязательное | Описание                  |
|---------------|----------|--------------|---------------------------|
| `id`          | Guid     | да           | Идентификатор события     |
| `title`       | string   | да           | Название события          |
| `description` | string?  | нет          | Описание события          |
| `startAt`     | DateTime | да           | Дата и время начала       |
| `endAt`       | DateTime | да           | Дата и время окончания    |
